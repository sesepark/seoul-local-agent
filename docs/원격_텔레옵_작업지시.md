# 원격 텔레옵(가상 리더) 작업지시와 실행 기록

이 문서는 세 부분이다. **1. 조사해서 확인한 사실**(전제), **2. 실제로 한 일**(2026-09-01,
맥 앱과 서버 양쪽), **3. 서버 Codex에게 남은 프롬프트**(아직 하지 않은 것).

기능 자체의 설명은 [사용 안내](사용_안내.md)의 `원격 텔레옵 (가상 리더)`에, 안전 문턱값과
미확인 항목은 [원격 텔레옵 안전 사다리](원격_텔레옵_안전.md)에, 계약은
[원격 텔레옵 계약](원격_텔레옵_프로토콜.md)에 있다.

## 1. 조사해서 확인한 사실 (2026-09-01, 실제 서버에 들어가서 확인)

- 서버: `deploy@192.168.0.20`, Ubuntu 22.04. 콘솔 저장소는 `/home/deploy/Project/so-arm-101`
  (= GitHub `sesepark/soarm101-console`). `soarm-console.service`는 **active**.
- 접속에 비밀번호가 필요 없다. 앱 전용 열쇠로 그냥 들어가진다:
  `ssh -i ~/Library/Application\ Support/SeoulLocalAgent/soarm-tunnel-key -o UserKnownHostsFile=~/Library/Application\ Support/SeoulLocalAgent/soarm-known-hosts deploy@192.168.0.20`
- LeRobot 0.6.1, Python 3.12, venv는 `.venv`. `uvicorn[standard]`가 딸려 오므로 **WebSocket이
  이미 된다**(`websockets` 17.1). `httpx`가 있어 `TestClient`로 WebSocket 시험도 된다.
- **LeRobot 0.6.1의 `SOFollowerConfig.use_degrees` 기본값이 `True`다.** 즉 팔로워의 액션
  단위는 도(degree)이고, 집게만 `MotorNormMode.RANGE_0_100`이 하드코딩되어 퍼센트다.
  `SOARM_MAX_RELATIVE_TARGET=2`는 **틱당 2도**라는 뜻이다.
- `MotorsBus._normalize()`의 도 변환은 `(raw - mid) × 360 / 4095`, `mid = (min+max)/2`.
  절대 한계는 여기서 계산한다. `_unnormalize()`는 도 단위에서 **값을 자르지 않는다**
  (RANGE_M100_100과 달리 clamp가 없다) — 범위 검사를 우리가 하지 않으면 그대로 모터에 실린다.
- 팔로워 calibration 실측 범위 → 절대 한계: pan ±118.2°, lift ±104.9°, elbow ±96.9°,
  wrist_flex ±102.7°, wrist_roll ±180°, gripper 0~100%.
- 카메라는 `GET /api/cameras/{scene|wrist}.mjpg`로 이미 나온다. 폰용 관찰 전용 페이지
  `/mobile`도 이미 있었다.
- **Tailscale이 깔려 있고 돌고 있다.** 서버(`sehwan`), 아이폰(`iphone183`), 맥북이 같은
  tailnet에 있다. 다만 **`tailscale serve`가 이 tailnet에서 아직 활성화되어 있지 않다** —
  계정 소유자가 브라우저에서 한 번 켜야 한다(3절).
- 서버에는 `claude`가 없고 `codex` 0.114.0이 있다(`/snap/bin/codex`).
- SO-ARM101 URDF는 상류 `TheRobotStudio/SO-ARM100`에 없다(STEP/STL만).
  `renesas-rdk/so_arm101_description`의 URDF는 **관절 이름이 LeRobot 모터 이름과 정확히
  같고** 한계가 0을 가운데 둔 라디안이라 도 단위와 그대로 대응한다. 메시는
  `timqian/bambot`(Apache-2.0)이 같은 파일을 갖고 있다.
- 서버 저장소에 커밋되지 않은 작업이 있었다(카메라 모드 조회, 데이터셋 API). 버리지 않고
  먼저 커밋했다(`7b8efe1`).

## 2. 실제로 한 일 (2026-09-01)

### 2.1 서버 (`sesepark/soarm101-console`, ssh로 직접)

커밋 `b85d77d`, `9d19901`. **push는 하지 않았다** — 원격에 올리는 것은 사용자가 결정할 일이다.

- `src/soarm_console/vleader/` 새 패키지 (7개 모듈, 약 1,800줄)
  - `spec.py` 관절 계약 — 절대 한계를 calibration에서 계산, URDF 대응과 라디안 변환 계수
  - `safety.py` 검사 사다리(`CommandValidator`)와 관측 트립(`TripDetector`), 문턱값 config
  - `authority.py` Follower motion lease — 동시에 하나, 빼앗기 없음, 순번 재생 방지
  - `owner.py` 30Hz 제어 루프 — 상태기계(SAFE/READY/ACTIVE/RETREATING/HOLD/FAULT), 물러남,
    워치독, 중계 모드
  - `backend.py` 실물(`SOFollower`)과 흉내 백엔드
  - `api.py` REST + WebSocket, 조작 토큰
  - `teleoperator.py` LeRobot `Teleoperator` 서브클래스 (`lerobot-record`용)
- `src/soarm_console/static/viewer/` 3D 뷰어 한 벌 — three.js r160, 직접 쓴 URDF 로더,
  URDF와 메시(정점 클러스터링으로 19MB → 1.9MB), `?host=web|native` 두 모드
- `app.py` — 라우터 연결, `/api/status`에 `virtual_leader` 블록, 모드 상호배타, `/viewer` 마운트,
  수집 시작에 `teleop: "leader"|"virtual"`
- `recording.py` / `record_manager.py` — 가상 리더로 찍을 때 리더 팔 calibration을 요구하지 않음
- `tests/test_vleader.py`, `tests/test_vleader_api.py` — 46개 (기존 27개와 합쳐 73개 통과)
- `scripts/measure_contact.py` — 접촉 문턱을 정하기 위한 읽기 전용 측정 도구. 토크를 스스로
  걸지 않는다. `quiescent` 단계만 실행했다(아래 2.3)
- 문서: `ADR/0002`, `ARCHITECTURE`/`PROTOCOL`/`SAFETY`/`FAILURE_MODES`의 구현 상태 갱신,
  `RUNBOOK` 6절(가상 리더), `README`, 뷰어 `ATTRIBUTION.md`

이어서 **서버의 Codex가** 아래를 더 했다(커밋 `54f3d0a`). 3절 프롬프트의 3~5번에 해당한다.

- `owner_lock.py` — 장치별 `flock` owner lock. 가상 리더·물리 텔레옵·수집·카메라·doctor·
  접촉 측정이 모두 이것을 거치고, child 프로세스에 descriptor를 물려준다. 강제 해제 경로는
  없고, 프로세스가 죽으면 커널이 풀어 준다. 설계와 복구 절차는 `ADR/0003`.
- `lerobot-teleoperate`와 `lerobot-record`에 `--robot.disable_torque_on_disconnect=false`.
  LeRobot의 기본값이 참이라 그 프로세스가 끝나는 순간 **팔이 떨어졌다.**
- `GET /api/vleader/motion-auth` — 아무것도 하지 않고 토큰만 확인한다(Tailscale 경로 점검용).
- `measure_contact.py`에 min과 온도 시작/끝/상승량 추가.
- `RUNBOOK`에 Tailscale 활성화 주소와 200/401/200 점검, 접촉 문턱 결정식, 온도 재검토 기준.
- `ADR/0004` — 수집 중 안전 사다리를 메울 방법의 조사 초안(구현은 하지 않음).

**그 작업을 받아 확인하면서 하나가 나왔다: 커밋과 시험 통과만으로는 서버에 반영되지 않는다.**
서비스가 재시작되지 않아 돌고 있던 것은 lock이 없는 옛 코드였고, 그래서 밖의 프로세스가
가상 리더가 쥔 팔로워를 그대로 다시 열어 읽었다 — lock이 막았어야 할 바로 그 상황이다.
재시작한 뒤에는 `Device is owned by virtual-leader (pid …)`로 거절된다. 확인 절차를
서버 `RUNBOOK` 6.0에 남겼다(커밋 `ce32f32`).
- `config/soarm.env`에 `SOARM_MOTION_TOKEN` 생성(커밋되지 않는 파일), `.env.example`에 설명
- 서비스 재시작. 현재 `state: STOPPED`, `preflight: []`, serial은 놓은 상태.

**하지 않은 것**: sudo, udev, docker, systemd 유닛 변경. `cookierunhub` 컨테이너는 건드리지
않았다. 팔을 움직이는 명령은 한 번도 보내지 않았다(토크를 건 적이 없다).

### 2.3 확인한 것 / 확인하지 못한 것

전부 `docs/원격_텔레옵_안전.md`의 "확인한 것" / "아직 확인하지 못한 것"에 적었다.
요약하면: 팔을 움직이지 않고 확인할 수 있는 것은 전부 실제로 걸어 보았고(리스 경쟁·만료·
워치독·잘못된 값 거절·자세 미동기 거절·재연결·카메라·터널 정리·프로세스 잔류),
**팔이 실제로 움직이는 것과 접촉 문턱의 실측값은 하지 않았다.**

맥 앱을 살아 있는 콘솔에 붙여 걸어 보다가 **안전에 관한 것 셋**이 드러났다.

- **확인 문구 게이트가 토크를 거는 자리에만 있었다.** 토크가 이미 걸려 있으면 그 자리를
  지나치므로, 먼저 켜 둔 사람이 있는 팔에 아무나 문구 없이 붙을 수 있었다. 팔이 움직일 수
  있게 되는 순간은 권한을 받는 순간이다 — 리스 발급에도 같은 문구를 요구하게 고쳤다.
- **이미 서 있는 팔에 새 정지 사유가 덮어써졌다.** 접촉으로 멈춘 팔에 "조작 권한을
  반납했습니다"라고 적혀 있는 것을 보았다. 팔을 세운 것은 처음 이유다.
- **반납으로 선 것과 정지로 선 것을 구별하지 않았다.** 앞의 것은 정상적인 교대라 새 사람이
  이어받으면 풀리고, 뒤의 것은 이유를 읽고 확인해야 풀린다.

그리고 실물에서 처음으로 숫자를 쟀다(`scripts/measure_contact.py quiescent`, 토크 끄고 25초):
쉬는 중의 부하와 전류는 전 관절 **0**, 온도는 팔 34~36°C에 **집게만 48°C**. 온도 경고를
55°C에서 58°C로 올린 근거가 그것이다 — 55°C면 집게는 평소에도 경고에 가깝고, 그런 경고는
진짜로 뜨거워졌을 때 아무도 믿지 않게 만든다.

그 밖에 기록해 둘 만한 것:

- 관절 **계약**과 관절 **현재값**을 같은 JSON 키에 담았더니 계약이 조용히 덮여 사라졌다.
  화면에는 관절이 하나도 없는데 서버는 정상이라고 말하는 상태였다. 키를 갈랐다.
- 텔레메트리 구독을 제어 루프가 들고 있었더니, 루프가 뜨기 전에 붙은 연결은 영영 아무것도
  받지 못했다. 화면을 먼저 열고 권한을 나중에 받는 것이 정상적인 순서인데도 그랬다.
- 하트비트를 명령에만 얹었더니, HOLD로 멈춰 서 있는 5초 사이에 조작 권한이 다른 기기로
  넘어갔다. `PROTOCOL.md`가 둘을 분리하라고 적어 둔 이유를 실물로 확인했다.
- 틱당 상한을 "명령당"으로 걸면 빠르게 보내는 클라이언트가 그만큼 빨리 움직인다. 시간으로
  나눴다.
- `SOArmServer`에 필드를 하나 늘렸더니 그 키가 없는 예전 설정 파일이 통째로 디코딩에
  실패하며 서버 주소와 계정까지 사라졌다(Swift가 합성하는 디코더는 기본값이 있어도 키가
  없으면 실패한다). 시험이 잡아냈다. 손으로 디코더를 썼다.
- `WKWebView`를 세로 스크롤 안에 넣었더니 웹 내용이 아예 그려지지 않았다. 스크롤 밖으로
  꺼냈고, 결과적으로 3D와 카메라가 늘 보이는 더 나은 배치가 되었다.
- 화면에 한 번도 표시된 적 없는 창에서는 WebKit이 `requestAnimationFrame`을 돌리지 않는다.
  그래서 창을 띄우지 않고 찍은 스크린샷에서 3D가 비어 보였다. 같은 페이지를 WebKit으로
  직접 열어 찍으니 91,490 삼각형이 그려졌다. 뷰어에 `soarmViewer.render()`를 두어 밖에서
  한 장 그리게 할 수 있다.

## 3. 서버 Codex에게 남은 프롬프트

앞 프롬프트의 3~5번(Tailscale 절차, owner lock, 수집 안전 사다리 조사)은 끝났다. 남은 것은
**사람이 팔 곁에 있어야만 되는 측정**과, 그 값이 나온 뒤의 반영이다. 그래서 짧아졌다.

```text
/goal 가상 리더의 접촉 문턱을 실측값으로 바꾸고, 수집 중 안전 사다리를 구현한다.
지금까지의 구현과 문서는 전부 들어와 있다(ADR 0002·0003·0004, src/soarm_console/vleader/,
owner_lock.py, scripts/measure_contact.py, RUNBOOK 6절, tests 79개 통과).

전제 (깨면 안 된다):
- 팔이 실제로 움직이는 명령은 보내지 않는다. 토크를 거는 것도 하지 않는다.
- 어떤 고장에서도 자동으로 토크를 끄지 않는다. 토크를 끄면 팔이 떨어진다.
- 하드웨어 소유자는 한 시점에 하나다. owner lock을 우회하는 경로를 만들지 않는다.
- 확인 문구를 미리 채워 주는 길을 만들지 않는다.
- sudo, udev, docker, systemd 유닛 변경은 사전 검토 없이 하지 않는다. cookierunhub 컨테이너·
  네트워크·볼륨은 건드리지 않는다.
- 코드를 고쳤으면 systemctl --user restart soarm-console 을 하고, RUNBOOK 6.0의 확인 한 줄로
  새 코드가 실제로 도는지 본다. 커밋과 pytest 통과만으로는 서비스에 반영되지 않는다 —
  지난번에 그래서 lock이 없는 옛 코드가 계속 돌았다.

할 일:

1. 사람이 handled / holding / contact 를 재고 나면(그 값은 사용자가 붙여 준다) RUNBOOK 6.7의
   빈 칸을 채우고 SOARM_VL_LOAD_TRIP과 SOARM_VL_CURRENT_TRIP을 다시 잡는다. 문턱은 holding의
   최대값과 contact의 최소값 사이여야 한다. 값이 아직 없으면 이 항목은 손대지 말고, 지금
   값이 유추값이라는 문장을 그대로 둔다.

2. 같은 값으로 온도 문턱을 재판정한다. 지금은 경고 58°C / 정지 65°C이고, 집게가 쉬는 중에도
   48°C라는 것이 58°C의 근거다. holding에서 얼마나 오르는지 보고 관절별 문턱이 필요하면
   RUNBOOK 6.9의 TOML 제안을 확정해 구현한다.

3. 수집 중 안전 사다리를 구현한다. ADR 0004가 후보를 정리해 두었으니 하나를 골라 ADR을
   Accepted로 바꾸고 구현한다. 지금은 lerobot-record가 버스를 쥐고 있어 부하·전류·온도·
   추종오차 감지가 없다 — 사람이 보고 있는 것 말고는 아무것도 없다는 뜻이다. 상류 LeRobot을
   포크해야 하는 안을 고른다면 그 비용과 유지보수 계획을 ADR에 함께 적는다.

4. flock이 advisory라는 한계는 문서에 그대로 두되, 저장소 규약 밖에서 LeRobot을 직접 돌리는
```
