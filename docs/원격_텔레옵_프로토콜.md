# 원격 텔레옵 계약

맥 앱, 아이폰 웹, 그리고 서버의 가상 리더가 주고받는 것. 서버 저장소 `soarm101-console`의
`PROTOCOL.md`가 정의한 봉투와 거절 코드를 이 기능에서 구체화한 것이고, 세 구현이 같은 계약을
읽어야 하므로 여기에 한 번만 적는다.

- **서버**: `src/soarm_console/vleader/` (별도 저장소 `sesepark/soarm101-console`)
- **맥 앱**: `Sources/SeoulLocalAgent/SOArmVirtualLeader.swift`, `SOArmTeleopModel.swift`
- **3D 뷰어**: 서버의 `static/viewer/` — 맥과 폰이 같은 파일을 쓴다

## 신뢰 경계

| 경로 | 어떻게 붙는가 | 관찰 | 조작 |
|---|---|---|---|
| 맥 앱 | SSH 로컬 포워딩 → `127.0.0.1:8088` | 그냥 | `X-SOARM-Motion-Token` |
| 아이폰 | Tailscale Serve (tailnet 전용 HTTPS) | 그냥 | 같은 토큰 |

콘솔 자체에는 인증이 없고 `127.0.0.1`에만 bind되어 있다. 그래서 *붙는 것*의 경계는 SSH 터널과
tailnet이고, 그 위에 **조작 권한만** 토큰으로 한 겹 더 가른다. 토큰은 서버
`config/soarm.env`의 `SOARM_MOTION_TOKEN`이며 저장소에 커밋되지 않는다. 비어 있으면 서버는
어떤 조작 권한도 발급하지 않는다 — 기본값이 열려 있는 쪽이면 설정을 잊었을 때가 곧 사고다.

## REST

전부 `/api/vleader` 아래. 🔑는 조작 토큰이 필요한 것.

| 메서드 | 경로 | 하는 일 |
|---|---|---|
| GET | `/api/vleader` | 관절 계약 + 정책 + 지금 상태. 아래 "상태" 참고 |
| GET | `/api/vleader/motion-auth` 🔑 | 아무것도 하지 않고 **토큰만** 확인한다. 200은 "이 요청이 지금 토큰을 안다"는 뜻이지 장치가 준비됐다는 뜻이 아니다 |
| POST | `/api/vleader/start` | 팔로워 serial을 잡고 30Hz 관찰을 시작한다. **토크는 걸지 않는다** |
| POST | `/api/vleader/stop` | 루프를 내린다. 토크가 걸려 있으면 409로 거절 (🔑 `?force=true`로만 강행) |
| POST | `/api/vleader/arm` 🔑 | `{"confirmation": "MOVE SOARM101"}` — 토크를 건다 |
| POST | `/api/vleader/torque/release` 🔑 | `{"confirmation": "RELEASE TORQUE SOARM101"}` — **팔이 떨어진다** |
| POST | `/api/vleader/lease` 🔑 | `{"confirmation": "MOVE SOARM101", "holder": "맥북", "session_id": "…"}` → 리스 하나. 문구가 틀리면 400, 이미 있으면 409 |
| POST | `/api/vleader/lease/{id}/heartbeat` 🔑 | 만료 시각을 밀어 준다 |
| DELETE | `/api/vleader/lease/{id}` 🔑 | 반납. 팔은 지금 자세에서 선다 |
| POST | `/api/vleader/hold` | **토큰도 리스도 필요 없다.** 지금 자세에서 세운다 |
| POST | `/api/vleader/resume` 🔑 | 멈춘 이유를 확인했다. 자세 동기화가 다시 요구된다 |
| GET | `/api/vleader/goal` | 중계 중인 목표. `lerobot-record` 안의 teleoperator가 매 틱 읽는다 |
| WS | `/api/vleader/stream` | 관찰과 조작이 함께 흐르는 연결 |

확인 문구가 `arm`과 `lease` 양쪽에 붙는 이유가 있다. 토크를 거는 자리에만 두었더니 토크가
이미 걸려 있을 때 그 게이트를 지나쳤고, 먼저 켜 둔 사람이 있는 팔에 아무나 문구 없이 붙을
수 있었다. 팔이 움직일 수 있게 되는 순간은 권한을 받는 순간이다. 화면에서는 한 번만 적고
앱이 그 하나를 두 요청에 함께 쓴다.

`/api/status`에도 `virtual_leader` 블록이 통째로 실린다. 기존 화면이 폴링만으로 이 기능의
상태를 알 수 있게 하기 위한 것이다.

### 상태

```jsonc
{
  "available": true,            // 관절 계약을 만들 수 있는가(=팔로워 calibration이 읽히는가)
  "spec_error": null,
  "preflight": [],              // 비어 있지 않으면 시작할 수 없다
  "spec": [                     // 관절 **계약**. 지금 값이 아니다
    {"name": "shoulder_pan", "label": "어깨 회전", "unit": "deg",
     "min": -118.1978, "max": 118.1978,
     "urdf_joint": "shoulder_pan", "urdf_sign": 1.0, "radians_per_unit": 0.01745329}
  ],
  "policy": { "hz": 30, "step_deg": 2.0, "load_trip": 400, ... },  // 안전 사다리의 문턱값
  "arm_confirmation_length": 13,  // 문구 자체는 내려주지 않는다. 화면이 대신 채우지 못하게
  "viewer_url": "/viewer/",

  "running": true,
  "relay": false,               // 참이면 장치를 놓고 목표만 중계하는 중(수집 시)
  "state": "ACTIVE",            // STOPPED SAFE READY ACTIVE RETREATING HOLD FAULT
  "state_korean": "조작 중",
  "torque_enabled": true,
  "observation": 27512,         // 관측 일련번호. 명령이 무엇을 근거로 했는지 되짚는 데 쓴다
  "loop_ms": 4.43,
  "joints": [                   // 지금 값
    {"name": "shoulder_pan", "present": -44.9, "goal": -44.9,
     "load": 77.2, "current": 21.9, "temperature": 32.0, "rate_limited": false}
  ],
  "fault": {"code": "OVERLOAD", "joint": "elbow_flex", "message": "…", "at": 1788195000.0},
  "warnings": [{"joint": "elbow_flex", "code": "OVER_TEMPERATURE", "message": "팔꿈치 58°C"}],
  "lease": {"lease_id": "…", "holder": "맥북", "needs_sync": false, "expires_in_ms": 4800},
  "command_age_ms": 33,
  "error": null
}
```

`spec`과 `joints`를 다른 키에 둔 것에는 사연이 있다. 처음에는 둘 다 `joints`였고, 상태를
합치는 자리에서 계약이 지금 값에 조용히 덮여 사라졌다. 화면에는 관절이 하나도 없는데 서버는
정상이라고 말하는 상태였다.

## WebSocket

`ws://127.0.0.1:8088/api/vleader/stream` (폰은 `wss://…`).

**붙는 데는 아무 권한도 필요 없다.** 관찰은 배타적이지 않다. 조작 권한은 연결이 아니라
**명령 하나하나**에 붙는다 — 유효한 `lease_id`가 실려 있을 때만 통한다.

### 서버 → 클라이언트

| type | 언제 | 내용 |
|---|---|---|
| `hello` | 붙자마자 한 번 | 위 "상태" 전체 |
| `telemetry` | 30Hz | 위 "상태"의 뒷부분(`running` 이하) |
| `ack` | 명령이 통과했을 때 | `{sequence, goal, rate_limited: [관절…], valid_for_ms}` |
| `reject` | 명령이 걸렸을 때 | `{sequence, code, joint, message}` |
| `lease` | 하트비트에 답할 때 | 리스 |
| `pong` | `ping`에 | — |

제어 루프가 돌지 않는 동안에도 0.5초마다 `telemetry`가 온다. 화면을 먼저 열고 조작 권한을
나중에 받는 것이 정상적인 순서인데, 그 사이에 아무것도 오지 않으면 화면은 서버가 죽은 것으로
읽는다.

`telemetry`는 밀리면 **오래된 것을 버린다**. 밀린 프레임을 순서대로 다 보내면 화면이 과거를
그리게 된다.

### 클라이언트 → 서버

```jsonc
{"type": "command",
 "lease_id": "426136b635229aff",
 "session_id": "mac-1a2b3c4d",
 "sequence": 128,              // 리스마다 1부터. 되돌아가거나 같은 값이면 거절
 "observation": 27512,         // 무엇을 보고 낸 명령인가. 15프레임보다 오래되면 거절
 "valid_for_ms": 300,          // 서버가 500ms로 자른다
 "joints": {"shoulder_pan": -44.9, "elbow_flex": 12.0}}   // 보내지 않은 관절은 지금 자리 유지

{"type": "heartbeat", "lease_id": "…"}
{"type": "hold"}
{"type": "ping"}
```

**하트비트는 명령과 따로 보낸다.** `PROTOCOL.md`가 둘을 분리하라고 적어 둔 이유가 구현하면서
그대로 드러났다: `HOLD`에 걸려 있는 동안에는 명령을 보내지 않으므로, 명령으로만 리스를
갱신하면 멈춰 서 있는 5초 사이에 조작 권한이 남에게 넘어간다. 실제로 넘어가는 것을 시험에서
한 번 봤다.

### 거절 코드

`PROTOCOL.md`에 이미 있던 것: `NO_ACTIVE_LEASE`, `WRONG_AUTHORITY`, `STALE_OBSERVATION`,
`EXPIRED_COMMAND`, `DUPLICATE_SEQUENCE`, `INVALID_SHAPE`, `NON_FINITE_VALUE`,
`OUTSIDE_ABSOLUTE_LIMIT`, `HARDWARE_NOT_READY`.

이 구현에서 추가한 것:

- `POSE_NOT_SYNCED` — 리스를 막 잡은 뒤 첫 명령이 팔의 현재 자세에서 너무 멀다.
- `NOT_ACCEPTING_MOTION` — 지금 `HOLD`/`RETREATING`/`FAULT`다. 사람이 확인해야 풀린다.

관측이 거는 정지는 명령의 거절이 아니라 `fault.code`로 온다: `OVERLOAD`, `OVERCURRENT`,
`FOLLOWING_ERROR`, `OVER_TEMPERATURE`, `COMMAND_TIMEOUT`, `LEASE_EXPIRED`, `LEASE_RELEASED`,
`OPERATOR_HOLD`, `HARDWARE_ERROR`.

클라이언트는 **모르는 코드를 일반 거절로 처리한다.** 조용히 무시하면 서버가 새 게이트를
추가했을 때 화면이 이유 없이 안 움직이는 것처럼 보인다.

## 단위

LeRobot의 `SOFollower` 액션 공간을 그대로 쓴다. 바꾸지 않는 이유는, 바꾸는 순간 그 변환식이
안전 검사와 실제 쓰기 사이에 끼어들기 때문이다.

- 팔 관절 다섯: **도(degree)**, 0을 가운데 둔 대칭 구간. `use_degrees=True`가 LeRobot 0.6.1의
  기본값이다.
- 집게: **0~100 퍼센트**. `SOFollower`가 집게에만 `RANGE_0_100`을 하드코딩해 두었다.

3D는 이 값을 `radians_per_unit`(서버가 준다)로 곱해 URDF 관절 각도로 바꾼다. 변환식을
클라이언트마다 다시 쓰면 맥과 폰이 같은 팔에 대해 다른 그림을 그린다.

## 3D 뷰어의 두 가지 host

같은 페이지가 두 기기를 그린다. 구현이 둘이면 두 기기의 동작이 반드시 어긋난다.

### `?host=web` — 아이폰

페이지가 자기 WebSocket을 열고, 관절 슬라이더·카메라·정지 버튼·확인 문구까지 자기 화면에
그린다. 조작 토큰은 `localStorage`에 남는다(그 기기에만).

### `?host=native` — 맥

페이지는 **그리기와 집기만** 한다. WebSocket도 리스도 앱이 쥔다. 두 곳에서 같은 리스로
명령을 보내면 순번이 엉키고 서버가 그중 하나를 중복으로 거절한다.

| 방향 | 통로 | 메시지 |
|---|---|---|
| 페이지 → 앱 | `window.webkit.messageHandlers.soarm` | `{type:'ready', renderer, triangles}` · `{type:'target', joints, commanding}` · `{type:'hold'}` · `{type:'grab', joint}` · `{type:'error', message}` |
| 앱 → 페이지 | `evaluateJavaScript` | `soarmViewer.spec(…)` · `soarmViewer.telemetry(…)` · `soarmViewer.setEnabled(bool)` · `soarmViewer.setTarget(name, value)` · `soarmViewer.endTarget()` · `soarmViewer.render()` |

`render()`는 한 장을 강제로 그린다. 창이 화면에 없거나 탭이 뒤에 있으면 브라우저가
`requestAnimationFrame`을 멈추는데, 그때도 마지막 상태를 한 장 그려야 하는 경우가 있다.

## 데드맨

3D에서 손을 떼면 목표가 **팔의 지금 자리로 붙는다.** 스트림은 계속 흐른다.

멈추는 것은 목표이지 대화가 아니다. 손가락을 뗄 때마다 스트림을 끊으면 서버의 워치독이
그것을 사고로 읽고 `HOLD`로 떨어뜨리는데, 그러면 매번 `확인하고 계속`을 눌러야 한다.
실제로 대화가 끊기는 것은 화면을 떠나거나 앱이 끝나거나 네트워크가 죽을 때이고, 그때는
`HOLD`가 정확히 옳은 답이다.

## 데이터 수집

`lerobot-record`가 팔로워 serial의 소유자가 된다. 그래서 콘솔은 장치를 놓고 중계 모드로
내려간다(`relay: true`). 그 사이 목표는 `GET /api/vleader/goal`로 나가고, record 프로세스
안의 `SOArmVirtualLeader`(LeRobot `Teleoperator` 서브클래스)가 매 틱 가져가 `get_action()`으로
돌려준다. 수집 화면은 새로 만들지 않았다 — `POST /api/recording/start`에 `"teleop": "virtual"`을
붙이는 것이 전부다.

중계 모드에서는 안전 사다리의 관측 쪽 칸이 없다. 그 차이는 `docs/원격_텔레옵_안전.md`에 적었다.
